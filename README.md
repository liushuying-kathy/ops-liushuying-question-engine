# 经营问题引擎

面向连锁生鲜经营分析的“问题发现—诊断下钻—角色分发”流水线。目标是把门店经营数据转化为可回溯、可审核、可行动的问题清单，而不是只展示指标涨跌。

> **当前状态：研发与业务评审中，不是已上线系统。** 本仓沉淀产品规则、引擎代码快照、角色样张、语义口径和逐日施工记录；全量数据、过程跑批产物及生产验证证据不随仓分发。

## 2. 主链路

1. **扫描与触发**：按日、月频率读取门店及上级组织经营数据，先通过数据质量与样本门槛。
2. **问题发现**：沿“财务结果 → 量 → 价链 → 钱 → 行为”定位异常，不以单一指标直接下业务因果结论。
3. **诊断下钻**：按组织单元树逐层下钻；可行动末梢为门店×品类×等级×日，告警末梢与诊断末梢分开处理。
4. **审核与萃取**：检查结构、重叠、遗漏、聚焦和行动性；重点问题需完成数量去向勾稽，校验失败时停止发布。
5. **角色渲染**：同一问题按 CEO/CFO、区总、运营经理、督导、店长等角色投影。CEO/CFO 同级，运营经理必须经督导组下钻，单店只看自己；所有角色先看财务结果，再看过程与动作。
6. **证据分级**：区分“数值事实、诊断线索、已确认原因”。量价或价格链贡献对平只证明数值分解闭合，不自动证明业务因果。

## 5. 工程使用边界

- 环境准备和脚本入口见 `engine/README.md`，密钥只放本机环境变量或 `.env`，不得提交真实令牌。
- 全量 Hive 导出、原始看板、过程 JSONL、`engine_output/`、`engine_runs/` 和截图均外置；仓内样例不能替代 production 数据验证。
- mock 与 production 必须分别验收；工程测试通过不等于业务发现质量通过。
- 本轮文档更新**不授权覆盖引擎代码或冻结配置**。涉及 `engine/config/thresholds.yaml`、`engine/config/metric_tree.yaml` 的变更必须单独 diff 和审核。
- `.html` 默认禁入；仅 `engine/demo/QDM全真演示稿_*.html` 锁版样张可按例外入库，且必须保留 RENDER-ONLY 注释并核对提交前后 SHA256。
