## 1. 做成什么（§1）

每天扫商分库，用不等式找出**已经成立**的经营问题。本阶段不写推送渠道、群、页面跳转。

发现顺序（固定）：

1. 入口：E1 → E2 → E3（并列判断，短清单只强调一条）
2. 定位：管理区域 → 运营大区 → 省 → 市 → 店型 → 品类（能汇总的层才发）
3. 过程：订购 → 销售 → 销售拆分 → 促销 → 消费者（一段只挂一个叶子）
4. 投影：按对象主键写入区域单 / 督导单 / 加盟商单 / 店长单
5. 月度两天：L2 写公司重要问题榜（§5.3）与会员槽；**日扫永不写 CEO 榜**

三条纪律：① 写不出不等式的叶子只标状态、不触发；② 日扫可出问题，不进公司重要问题榜；③ 解法可空，没有建议动作不算失败。

## 2. 四层架构与工程入口（§15 / §15.1）

```text
定时/手动 → 取数 → run_batch → checks → 树/榜 → 角色呈现
L1 穷尽发现 → L2 80% 提炼 → L3 问题树/下发包 → L4 对象投影
```

- 工程入口：`scripts/run_batch.py`、`engine/`（落地方案 §15）。
- Windows 计划任务入口：`scripts/scheduled_run.ps1`（设 `ENGINE_RUN_DIR=问题引擎\runs\{当天}`，再调 `run_batch.py` 与 `run_v33_grader.py`）。
- 生产化（§14）：每次跑批重新 bdapp + 神策 CLI；跨日状态 `runs/state/episodes.json`；计划任务固定机 Windows 任务调度；凭证失效则失败并写 `report.json`，不读过期快照。

【待核】§14 与「Windows 计划任务说明.md」是否需并列引用（冷阅读评估）。

## 3. 日历门（§5.1）

法定假日及前后 1 日、农历错位日：**不升级，不进公司重要问题榜**。管理区域日提示仍可出；`event_label` 写假日名或「农历错位，对照日 YYYY-MM-DD」；`alert_level` 仍是提示。标注不改变不等式。

---

## 4. 每日扫描（§5.2）

要点摘录：

1. 对 `calendar_status`。
2. 会员：T15、T10 的日/预提示规则不变。
3. **入口：E1 没有日净利，日扫跳过 E1**；月度 E1 走月表；当日入口从 E2 起。
4. 过程：店级整店行按 T+1；`daily_scan.delay_checked=true`；**促销不进日扫**。
5. **日扫不进公司重要问题榜**。管理区域层日提示默认开；`daily_scan.open_store_layer=true` 时店×日与月频同阈值，定比 364，不进 CEO 榜。
6. **每个在营管理区域当日只下发一条**（区域日路径择一；五步同比 < 0 阶梯，见方案正文）。
7. 跨日合并：同区同叶子更新 `streak_days`，不新开 `episode_id`；断一天或叶子变 → 新存续。
8. 日下发呈现：`问题清单_区域日下发_样张.md`（权威 run 见 `02_样张索引.md`）。

## 5. 每月 · 公司重要问题榜（§5.3）

- 候选池（L1）→ 按贡献累加至 `ceo_view.fold`（默认 0.80）切片（L2）→ 下发包呈现（L3）。
- CFO 轨：`cfo_upgrades` + `问题清单_CFO重要问题榜.md`。
- 日扫行**永不进榜**；T12 品类、并行片不进榜排序但必须进下发包。
- v3 回退：`ceo_view.mode` ≠ `national_contribution_fold` 时回退「每管理区 E1→E2→E3 择一」。

验收权威样张：`runs/2026-10-18/`（见 `02`）。
